Interference & Phase

Superposition alone is not what makes a quantum computer powerful. The real engine is interference — and interference is driven by something measurement can never show you directly: phase.

What Phase Actually Is

So far we have described a qubit by how likely it is to measure as 0 or 1. That is only half the story. Each of the two possibilities carries an amplitude, and an amplitude has not only a size but also a direction — a kind of timing or orientation. That extra direction is called the phase.

Think of two identical waves. If they line up crest-to-crest, they add and get bigger. If one is shifted so its crest meets the other's trough, they cancel to nothing. The waves are the same size either way; what changed is their relative timing. Phase is that timing, attached to each amplitude of a quantum state.

The catch: if you simply measure a qubit, phase is invisible. Two states with identical measurement probabilities but different phases give you exactly the same 50/50 statistics. Phase only reveals itself when you let paths recombine — that is, when you apply another gate and let the amplitudes interfere.

The Demo: H → H versus H → Z → H

Here is the cleanest possible demonstration in all of quantum computing, and it fits in three gates.

  1. Start a single qubit in |0⟩.
  2. Apply H. The qubit is now in an equal superposition: measuring here would give 0 half the time and 1 half the time.
  3. Now either apply H again immediately, or insert a Z gate first and then the second H.
  4. Measure.

The two circuits pass through what looks like the same 50/50 superposition in the middle. Yet:

  • H → H returns |0⟩ with certainty — 100% of shots read 0.
  • H → Z → H returns |1⟩ with certainty — 100% of shots read 1.

Nothing random survives. Two circuits whose midpoints have identical measurement statistics end in opposite, perfectly certain outcomes. The only difference between them is a phase.

Run It Yourself

from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator
from qiskit.visualization import plot_histogram

sim = AerSimulator()

# Circuit A: H -> H   (no phase flip)
qc_a = QuantumCircuit(1, 1)
qc_a.h(0)
qc_a.h(0)
qc_a.measure(0, 0)

# Circuit B: H -> Z -> H   (phase flip in the middle)
qc_b = QuantumCircuit(1, 1)
qc_b.h(0)
qc_b.z(0)          # flips the sign of the |1> amplitude
qc_b.h(0)
qc_b.measure(0, 0)

counts_a = sim.run(transpile(qc_a, sim), shots=1000).result().get_counts()
counts_b = sim.run(transpile(qc_b, sim), shots=1000).result().get_counts()

print("H -> H     :", counts_a)   # {'0': 1000}
print("H -> Z -> H:", counts_b)   # {'1': 1000}

plot_histogram([counts_a, counts_b], legend=["H-H", "H-Z-H"])

Why It Happens

After the first H, the qubit holds two amplitudes — one attached to |0⟩ and one attached to |1⟩ — both the same size, both pointing the same way.

The Z gate leaves |0⟩ alone and flips the sign of the |1⟩ amplitude. That is a pure phase change: the sizes are untouched, so if you measured right there you would still see a flat 50/50. Nothing observable has changed — yet.

The second H is where the payoff lands. H takes each of the two amplitudes and spreads it across both outcomes, so every final outcome is reached by two different routes. Those routes then add:

  • Without the Z: the two routes into |0⟩ point the same way and reinforce (constructive interference), while the two routes into |1⟩ point opposite ways and annihilate (destructive interference). Result: certain |0⟩.
  • With the Z: the sign flip swaps which pair reinforces and which cancels. Result: certain |1⟩.
This is the real mechanism behind quantum speedups. A quantum computer does not "try every answer at once and read them all out" — you only ever get one measurement result. What an algorithm does is arrange the phases so that the routes leading to wrong answers cancel each other out, while the routes leading to the right answer reinforce. Superposition supplies the routes; interference does the computing.
Looking ahead: Grover's algorithm (Chapter 10, built by hand in Chapter 11) is exactly this trick scaled up. Its "oracle" step flips the phase of the marked answer — just like the Z above — and its diffusion step is the interference stage that converts that invisible phase flip into a visible probability. Everything you just saw with one qubit is the whole idea.
For the curious: the matrices

None of this is needed to follow the chapter, but if you want to check the arithmetic by hand:

H = 1/sqrt(2) * [[1,  1],
                 [1, -1]]

Z =             [[1,  0],
                 [0, -1]]

|0> = [1, 0]

H|0>      = (1/sqrt(2)) [1,  1]      -> 50/50, both amplitudes positive
ZH|0>     = (1/sqrt(2)) [1, -1]      -> still 50/50, but the sign flipped
H H |0>   = [1, 0] = |0>             -> certain 0
H Z H |0> = [0, 1] = |1>             -> certain 1

Note that H·H is the identity matrix — H is its own inverse. Inserting Z between the two H gates turns "undo what you just did" into "do the opposite."

A Practical Gotcha: How Qiskit Prints Bits

Before you go interpreting histograms, one convention will trip you up at least once. When Qiskit prints a multi-bit result string, it puts the highest classical-bit index on the LEFT and the lowest on the right — the opposite of the reading order most people assume.

A Worked Example

from qiskit import QuantumCircuit, transpile
from qiskit_aer import AerSimulator

qc = QuantumCircuit(2, 2)
qc.x(0)                  # flip qubit 0 only; qubit 1 stays |0>
qc.measure([0, 1], [0, 1])

sim = AerSimulator()
print(sim.run(transpile(qc, sim), shots=100).result().get_counts())
# {'01': 100}   <-- NOT '10'

We flipped qubit 0, so you might expect the string '10' — "first qubit is 1." Qiskit prints '01' instead. Read the string right-to-left:

Position in the printed string '01'CharacterWhich classical bitWhich qubit measured into it
Left0c[1]qubit 1 (never flipped)
Right1c[0]qubit 0 (we applied X)
Why this matters for Bell states: a Bell state only ever produces '00' and '11', which are symmetric, so the ordering never bites you there. The moment you build a circuit where the qubits disagree, '01' versus '10' becomes the difference between "my circuit works" and "my circuit is backwards." Many hours have been lost to this.
Habit to adopt now: whenever you print or plot counts, say out loud (or in a comment) what each character means — for example # bits printed as c1 c0; c0 is the coin qubit. Stating it explicitly costs one line and removes the ambiguity permanently. Qiskit's plot_histogram uses this same ordering on its axis labels.
