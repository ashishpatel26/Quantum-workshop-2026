Capstone: True Quantum Random Number Generator

Everything you've learned — superposition, measurement, the simulator — comes together to build something genuinely useful: a random number generator that is actually random, not just random-looking.

The Full Code

from qiskit import QuantumCircuit
from qiskit_aer import AerSimulator

def quantum_random_bits(num_bits):
    """Generate truly random bits using quantum superposition"""
    qc = QuantumCircuit(num_bits, num_bits)
    qc.h(range(num_bits))          # put every qubit in superposition
    qc.measure(range(num_bits), range(num_bits))

    simulator = AerSimulator()
    result = simulator.run(qc, shots=1).result()
    bitstring = list(result.get_counts().keys())[0]
    return bitstring

# Generate an 8-bit random number
random_bits = quantum_random_bits(8)
random_int = int(random_bits, 2)

print(f"Random bits: {random_bits}")
print(f"Random integer (0-255): {random_int}")

Why This Is Actually Random

Every qubit is put into an equal superposition with a Hadamard gate, then measured exactly once. Quantum measurement isn't like rolling a physical die whose outcome is technically determined by initial conditions we just can't track (air currents, exact throw force, etc.) — the outcome of measuring a qubit in superposition is fundamentally undetermined until the moment of measurement. There is no hidden state that "already decided" the answer in advance.

Classical "random" isn't: Python's random.randint() and virtually every classical random number generator is a pseudo-random number generator (PRNG). Given the same seed, it produces the exact same sequence every time — it just looks unpredictable because the seed (often the system clock) is hard to guess. It's deterministic under the hood. A quantum measurement has no such seed to reconstruct: it's provably, not just practically, non-deterministic.

Real-World Use Cases

Cryptographic Keys

Encryption keys are only as strong as their randomness. A predictable "random" key generator is a security hole; true quantum randomness closes it.

Secure Tokens

Session tokens, one-time passwords, and API keys all rely on unpredictability to resist guessing attacks.

Fair Lottery Systems

Verifiable, provably-unbiased randomness matters anywhere fairness must be trusted publicly — lotteries, draws, and audits.

Extend It Live: Idea A — PIN / Password Generator

Map the random bits onto a character set to build a quantum-seeded password generator:

import string

def quantum_password(length=12):
    charset = string.ascii_letters + string.digits + "!@#$%^&*"
    bits_needed = length * 8  # generous entropy per character
    bits = quantum_random_bits(bits_needed)

    password = ""
    for i in range(length):
        chunk = bits[i*8:(i+1)*8]
        index = int(chunk, 2) % len(charset)
        password += charset[index]
    return password

print(quantum_password(12))

Extend It Live: Idea B — Compare Against Classical Randomness

import random

# Classical pseudo-random (deterministic given a seed)
random.seed(42)
classical_value = random.randint(0, 255)
print(f"Classical (seeded): {classical_value}")

random.seed(42)
classical_value_again = random.randint(0, 255)
print(f"Classical (same seed again): {classical_value_again}")
# -> identical every time: pseudo-random, not truly random

# Quantum: no seed exists to reproduce
quantum_value = int(quantum_random_bits(8), 2)
print(f"Quantum: {quantum_value}")

Run the classical block twice with the same seed and you'll get the exact same number both times — that's determinism hiding behind the word "random." There is no seed you can set for the quantum version that will reproduce a chosen output; the non-determinism is a property of physics, not of missing information.

You built a quantum random number generator. That's the whole workshop's arc: superposition → measurement → a genuinely useful, genuinely non-classical result.
