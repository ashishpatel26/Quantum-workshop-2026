Pre-Workshop Setup Guide

Fifteen minutes now saves everyone time on the day. Follow these steps in order and run the smoke test at the end.

Day-of buffer: we build in +15–20 minutes at the start of the workshop for stragglers and install hiccups, and TAs float the room to help — so don't panic if something doesn't work immediately. But doing this now means you spend that time learning quantum computing instead of fixing pip.

01 Check Python

You need Python 3.10 or newer. Check your version:

python --version

Expect something like Python 3.11.6. If you see Python 2.x, or the command isn't found, try python3 --version instead. If you don't have Python 3.10+, install it from python.org/downloads before continuing.

02 Create & Activate a Virtual Environment

A virtual environment keeps workshop packages isolated from the rest of your system.

python3 -m venv entangle-env
source entangle-env/bin/activate

Your prompt should now start with (entangle-env).

python -m venv entangle-env
entangle-env\Scripts\Activate.ps1

Using Command Prompt instead of PowerShell? Run entangle-env\Scripts\activate.bat instead. See the troubleshooting section below if PowerShell blocks the script.

03 Install Qiskit & Friends

With your virtual environment active, install everything we'll use today:

pip install qiskit qiskit-aer matplotlib jupyter notebook

This pulls in:

  • qiskit — the core quantum SDK (circuits, gates, visualization)
  • qiskit-aer — the high-performance local simulator we'll run circuits on
  • matplotlib — used by Qiskit's plotting functions (histograms, Bloch spheres)
  • jupyter / notebook — for running code interactively during the labs

04 Smoke Test

Confirm everything installed correctly. Create a file called smoke_test.py with:

import qiskit
print(qiskit.__version__)

Run it:

python smoke_test.py
Expected output: a version string such as 1.2.4 (any recent 1.x or 2.x release is fine). No traceback, no red text.

If it fails, check the Troubleshooting section below before the workshop — or just bring your laptop as-is, a TA will help you get set up in the first 15–20 minutes.

05 Weak Wifi at the Venue?

Offline fallback: conference wifi struggles when 40 laptops all run pip install at once. If you know the venue has weak wifi, download the wheel files ahead of time on a fast connection with: 
pip download qiskit qiskit-aer matplotlib jupyter notebook -d qiskit_wheels/
Bring the qiskit_wheels/ folder on a USB stick, and on the day install offline with: 
pip install --no-index --find-links=qiskit_wheels/ qiskit qiskit-aer matplotlib jupyter notebook
Organizers: consider bringing a few spare USB sticks pre-loaded with wheels for attendees who couldn't prep in advance.

06 Troubleshooting

"pip: command not found" / "pip is not recognized"

Your Python install may not have added pip to PATH. Try python -m pip install ... (or python3 -m pip ...) instead of calling pip directly — this routes through the Python interpreter you know is on PATH.

Windows: "cannot be loaded because running scripts is disabled on this system"

PowerShell's execution policy is blocking the venv activation script. Run PowerShell as your normal user (not admin) and allow scripts for your current session only:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

Then re-run entangle-env\Scripts\Activate.ps1. This only affects the current terminal window, not your whole system.

Version conflicts / "ResolutionImpossible" during install

Usually caused by an old global package clashing with Qiskit's dependencies. Make sure you actually activated the virtual environment (prompt shows (entangle-env)) before installing — if you skipped that step, packages installed globally can conflict. If problems persist, delete the venv folder and recreate it fresh:

rm -rf entangle-env   # or: rmdir /s entangle-env on Windows cmd
python -m venv entangle-env
Import error / DLL load failed on Windows

Usually means a mismatched Python architecture (32-bit vs 64-bit) or a very old Python version. Reinstall the 64-bit Python 3.10+ installer from python.org and recreate your virtual environment.

Still stuck? Don't spend the night debugging — bring your laptop as-is. We build in 15–20 minutes at the start of the workshop specifically for this, and TAs will be floating the room ready to help.
